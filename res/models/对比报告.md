# 三模型 RAG 效果对比报告

> 生成时间：2026-08-20 20:02:24

## 1. 实验概述

- **评测集**：30 个问答对（覆盖 16 个新能源汽车标准）
- **检索管线**：意图路由 → HyPE + BM25 → RRF → U型排序（三模型共用，完全相同）
- **评测裁判**：固定 DeepSeek（保证公平；检索指标一致，差异来自生成模型）
- **模型**：A=DeepSeek 云 API；B=本地 qwen2:7b（ollama，未微调）；C=qwen2:7b QLoRA 微调（LoRA，基于标准问答数据 957 条）
- **⚠️ C 的说明**：C 为 **1 epoch 的中断 checkpoint（120/240 steps，loss 1.44 仍在下降，未收敛）**，且微调数据为「裸问答」格式、与推理的 `<docs>` 上下文格式不一致；忠实度评测 30 题中有 13 题裁判超时（NaN）。三项因素都会压低 C 的指标，方向（C < B）稳健，但绝对值存在测量噪声。

## 2. 平均指标对比

| 模型 | 忠实度 | 答案相关性 | 上下文精确率 | 上下文召回率 |
|---|---|---|---|---|
| A DeepSeek 云 | 0.9224 | 0.8629 | 0.7588 | 0.9833 |
| B qwen2:7b 未微调 | 0.6450 | 0.8487 | 0.7731 | 0.9667 |
| C qwen2:7b 微调 | 0.1933 | 0.4776 | 0.7641 | 0.9500 |

## 3. 结论

**结论：按当前方案（957 条裸问答、1 epoch、QLoRA）微调，未提升反而显著降低本地 7B 的 RAG 忠实度，预期「DeepSeek ≈ 微调后模型 > 未微调 7B」被证伪。**

- **微调效果（C vs B）**：忠实度 Faithfulness ▼0.4517；答案相关性 Answer Relevancy ▼0.3711；上下文精确率 Context Precision ▼0.0090；上下文召回率 Context Recall ▼0.0167
- 检索侧指标（精确率/召回率）三者几乎一致（差异来自生成模型；C 因回答长导致召回率略降），恶化集中在**生成侧**（忠实度、相关性）。
- C 的实际回答表现为「短答案 + 大段原文照抄」，且大量触发裁判超时，与微调数据未含 `<docs>` 上下文、模型未学会按检索上下文回答高度相关。
- **处置决定（2026-08-20）**：接受负面结论，不做续训/重训。生产环境 RAG 生成使用 DeepSeek 云；本地 ollama qwen2:7b 保留为离线兜底。若后续要再试微调，应先让训练数据与推理提示格式一致（带 `<docs>` 上下文）并训练至收敛。
